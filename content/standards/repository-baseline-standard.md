The branching, CI and code review standards all assume the repository underneath them is set up correctly: the default branch is protected, code owners exist, the pipeline comes from the central templates, secrets are blocked at push. In practice repositories are created by hand, settings drift, and nobody notices until a force-push erases a release or a token lands in history. This standard lists the baseline every repository must have from its first commit, says which platform setting implements each rule on GitLab and on GitHub, and gives read-only scripts that audit it.

It does not repeat the rules it relies on: protection and merge method are defined in [[branching-and-merge-standard]], pipeline content in [[ci-pipeline-standard]], review practice in [[code-review]] and update automation in [[dependency-update-policy]]. New repositories get the baseline from the template in [[architecture/golden-path-templates-architecture]].

## Scope

Applies to every repository that holds infrastructure code, service code, CI templates, policies or runbooks, on GitLab (our default) or GitHub. Personal sandboxes and forks used only to prepare a contribution are out of scope until they become a team's source of truth. Where the platforms differ, both are named.

> [!info] Keywords and plan tiers
> MUST means the audit job or a reviewer flags the repository as non-compliant. SHOULD means the owning team records why it deviates. The rules are team policy; the settings that implement them come from the vendor documentation checked on 2026-10-21. Several settings depend on the plan: on GitLab, code owners, approval rules, push rules and group-based branch permissions need Premium or Ultimate, and secret push protection needs Ultimate. On GitHub, code owners and rulesets on private repositories, organisation rulesets, secret scanning and push protection depend on the plan. Check the docs for your plan and version before you make a rule a gate.

## Required files

| File                            | Required for                         | Rule                                                                                                                           |
| ------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `README.md`                     | All                                  | MUST have the sections listed below                                                                                            |
| `CODEOWNERS`                    | All                                  | MUST exist, with team aliases only; covers CI, infrastructure and policy paths and the file itself                             |
| `catalog-info.yaml`             | All                                  | MUST name the owner group and, for services, the tier; format per [[architecture/internal-developer-platform-architecture]]    |
| `.gitignore`                    | All                                  | MUST exclude local state and secrets files (`.env`, `*.tfstate`, `.terraform/`, key files)                                     |
| `.editorconfig`                 | All                                  | MUST set `root = true`, `charset`, `end_of_line`, `insert_final_newline` and `trim_trailing_whitespace`                        |
| `.pre-commit-config.yaml`       | All                                  | MUST include the secret scan from [[secret-scanning-pre-commit-and-ci]]; SHOULD include the repository's linters               |
| CI configuration                | All                                  | MUST include the central templates at a pinned version ([[adr/0013-versioned-central-ci-templates]]); no hand-copied pipeline  |
| Dependency update configuration | All with dependencies                | MUST exist for the update bot chosen in [[dependency-update-policy]]                                                           |
| `CHANGELOG.md`                  | Repositories that release artifacts  | MUST follow [Keep a Changelog](https://keepachangelog.com/) or be generated by [[release-versioning-and-changelog-automation]] |
| `LICENSE`                       | Public repositories                  | MUST, chosen with [[compliance/open-source-license-compliance]]                                                                |
| `SECURITY.md`                   | Public repositories                  | MUST say how to report a vulnerability privately; see GitHub's docs on security policies for supported locations               |
| `CONTRIBUTING.md`               | Public and inner-source repositories | SHOULD, per [[management/inner-source-platform]]                                                                               |

**CODEOWNERS location and matching.** GitLab reads the first file it finds in `CODEOWNERS`, `docs/CODEOWNERS`, `.gitlab/CODEOWNERS`, in that order. GitHub reads `.github/CODEOWNERS`, then the root, then `docs/`, and only the file on the pull request's base branch counts. On both, the **last matching pattern wins** (on GitLab, per section: when a path matches entries in several `[Section]` blocks, the last match in each section applies), so put the default `*` line first and specific paths after it. GitHub skips invalid lines silently and does not support `!` negation or `[ ]` ranges; list errors with `gh api repos/OWNER/REPO/codeowners/errors`. Owners on GitHub need write access, and teams must be visible. GitHub limits the file to 3 MB.

**README sections** (MUST, headings may be translated into the repository's style):

1. What it is and why it exists, in two or three sentences.
2. Owner: team alias, chat channel and on-call rotation link. Never a person's name alone.
3. Service tier and data classification, with links to [[service-tiering-standard]] and [[data-classification-and-handling-standard]] (services and data stores only).
4. How to build, test and run it locally, as copy-paste commands.
5. How it is deployed or released, and how to roll back.
6. Links to runbooks, dashboards and SLOs for anything running in production.

```ini title=".editorconfig"
root = true

[*]
charset = utf-8
end_of_line = lf
insert_final_newline = true
trim_trailing_whitespace = true
indent_style = space
indent_size = 2

[*.{py,tf}]
indent_size = 4

[Makefile]
indent_style = tab

[*.md]
trim_trailing_whitespace = false
```

Later sections override earlier ones, so the general `[*]` block comes first. Change the indentation rules to match your formatters (Terraform's formatter, for example, decides HCL indentation itself); the point is that editors and formatters agree.

## Ownership metadata

Every repository answers "who owns this, how critical is it, and who do I page" without a search.

- **Catalog descriptor.** `catalog-info.yaml` names the owner group (never a person), the lifecycle and, for services, the tier. The owner must resolve to a real group in the identity source.
- **Tier.** Recorded as the annotation `example.com/service-tier` with a value from `tier-0` to `tier-3`, the same value used for the `example.com/service-tier` label on Kubernetes namespaces and the `service-tier` label on GCP projects ([[service-tiering-standard]]). Change `example.com` to your own domain prefix.
- **Platform metadata.** GitLab has no native field for owner or tier; use project topics for search (`team-reports`, `tier-1`) and keep the descriptor as the source of truth. GitHub offers repository custom properties (read and written with `GET` and `PATCH /repos/{owner}/{repo}/properties/values`); define the properties at organisation level and fill them from the descriptor. How custom property schemas are defined was not verified here; check the GitHub docs.
- **Archived or deprecated** repositories keep their owner, so someone answers for them until they are deleted under [[management/decommissioning-platform-services]].

## Settings

The policy column is ours. The setting columns name what implements it; setting names in bold are as the docs showed them on 2026-10-21, and UI labels move between versions.

| Policy (MUST unless marked)                                          | GitLab                                                                                   | GitHub                                                                                                                    |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Default branch protected; no direct push, no force-push, no deletion | Protected branch with **Allowed to push** set to no one, **Allowed to force push** off   | Ruleset on the default branch with `pull_request`, `non_fast_forward` and `deletion` rules (or classic branch protection) |
| Merge only through a reviewed request with passing pipelines         | Approval rules; **Pipelines must succeed**; skipped pipelines do not count               | `pull_request` rule with `required_approving_review_count`, `required_status_checks` rule                                 |
| Code-owner approval on owned paths                                   | **Require approval from code owners** on the protected branch                            | `require_code_owner_review` in the `pull_request` rule                                                                    |
| Stale approvals dismissed on new pushes                              | Approval settings for removing approvals on new commits (check the name in your version) | `dismiss_stale_reviews_on_push`                                                                                           |
| Conversations resolved before merge                                  | **All threads must be resolved**                                                         | `required_review_thread_resolution`                                                                                       |
| Merge commits ([[branching-and-merge-standard]])                     | Merge method **Merge commit**                                                            | Allow merge commits only; squash and rebase off (or `allowed_merge_methods` in the ruleset)                               |
| Source branch deleted after merge                                    | **Delete source branch** option enabled by default                                       | **Automatically delete head branches**                                                                                    |
| Secrets blocked at push                                              | Secret push protection (Ultimate) plus pipeline secret detection                         | Secret scanning push protection (plan dependent) plus the CI scan                                                         |
| Dependency updates and alerts on                                     | The update bot from [[dependency-update-policy]]; dependency scanning where licensed     | Dependabot alerts and security updates, or the chosen bot                                                                 |
| Release tags `v*` protected                                          | Protected tags                                                                           | Tag ruleset                                                                                                               |
| Signed commits (SHOULD)                                              | Push rule **Reject unsigned commits** (Premium or Ultimate)                              | `required_signatures` rule                                                                                                |

Notes on the platform differences:

- **GitLab protected branches versus GitHub rulesets.** GitLab has one protection entry per branch pattern. GitHub rulesets can layer (several rulesets apply to one branch at once), have an **evaluate** mode that reports without enforcing (rulesets are `disabled`, `active` or `evaluate`), and up to 75 rulesets per repository. Roll out a new GitHub rule in evaluate mode first, the same audit-then-enforce path as [[policy-rollout-audit-to-enforce]].
- **Bypass.** On GitLab, users allowed to push and merge to a protected branch can bypass merge requests and therefore code-owner approval. On GitHub, ruleset bypass actors can be roles, teams or apps. Both lists stay empty for humans; release automation is the only allowed bypass ([[branching-and-merge-standard]]).
- **Secret push protection is not complete.** GitLab's push protection detects only high-confidence patterns, so tokens with custom prefixes are not caught; on self-managed and Dedicated the instance must allow it first. Keep the pipeline scan as well.

## Visibility and archiving

- **Private by default.** GitLab `internal` visibility opens a project to signed-in users across the instance (check the visibility docs for how external users are treated), which is wider than most teams intend; review it like public. A repository becomes public only through the open-source release process, with a review of its history for secrets and internal references first.
- **Archive, do not delete,** when a repository is retired: archiving keeps history for audits and incident archaeology. On GitLab, `POST /projects/:id/archive` archives a project. Record the decision and the replacement in the README before archiving.
- **No abandoned repositories.** A repository with no owner group, or with an owner group that no longer exists, is either adopted or archived within a month of the finding (proposed team default).

## Audit

Two checks, both read-only. The file check runs in each repository's own pipeline; the settings audit runs centrally on a schedule ([[scheduled-jobs-standard]]) with a read-only token and reports to the owning teams.

### File check in the repository pipeline

```bash title="scripts/check-repo-baseline.sh"
#!/usr/bin/env bash
#
# check-repo-baseline.sh - fail when the repository is missing baseline files.
#
# Usage: check-repo-baseline.sh [--public] [--releases]
# Exit codes: 0 ok, 1 baseline files missing, 2 bad usage.
#
set -Eeuo pipefail

readonly SCRIPT_NAME="${0##*/}"
PUBLIC=0
RELEASES=0
missing=0

usage() { printf 'Usage: %s [--public] [--releases]\n' "$SCRIPT_NAME" >&2; exit 2; }
fail() { printf 'MISSING  %s\n' "$*"; missing=$((missing + 1)); }
ok() { printf 'OK       %s\n' "$*"; }

tracked() { git ls-files --error-unmatch -- "$1" >/dev/null 2>&1; }

require_file() {
  if tracked "$1"; then ok "$1"; else fail "$1"; fi
}

require_one_of() {
  local label="$1" f
  shift
  for f in "$@"; do
    if tracked "$f"; then ok "${label} (${f})"; return 0; fi
  done
  fail "${label} (one of: $*)"
}

require_readme_section() {
  if grep -qiE "^#{1,3} .*$1" README.md 2>/dev/null; then ok "README section: $1"; else fail "README section: $1"; fi
}

main() {
  while [[ $# -gt 0 ]]; do
    case "$1" in
      --public) PUBLIC=1 ;;
      --releases) RELEASES=1 ;;
      *) usage ;;
    esac
    shift
  done

  require_file README.md
  require_file .gitignore
  require_file .editorconfig
  require_file .pre-commit-config.yaml
  require_file catalog-info.yaml
  require_one_of "CODEOWNERS" CODEOWNERS docs/CODEOWNERS .gitlab/CODEOWNERS .github/CODEOWNERS
  require_one_of "CI configuration" .gitlab-ci.yml .github/workflows/ci.yml
  for section in Owner Deploy Runbook; do
    require_readme_section "$section"
  done
  if [[ "$RELEASES" == "1" ]]; then require_file CHANGELOG.md; fi
  if [[ "$PUBLIC" == "1" ]]; then
    require_one_of "LICENSE" LICENSE LICENSE.md
    require_one_of "SECURITY.md" SECURITY.md .github/SECURITY.md docs/SECURITY.md
  fi

  if [[ "$missing" -gt 0 ]]; then
    printf '%s: %d baseline item(s) missing\n' "$SCRIPT_NAME" "$missing" >&2
    exit 1
  fi
}

main "$@"
```

`git ls-files --error-unmatch` checks that the file is **tracked**, not just present in the job's workspace. Change the README section names and the CI file list to your conventions; the GitHub workflow name `ci.yml` is an example.

### Settings audit: GitLab

```bash title="scripts/audit-gitlab-repo.sh"
#!/usr/bin/env bash
#
# audit-gitlab-repo.sh - read-only audit of one GitLab project's baseline settings.
#
# Usage: GITLAB_TOKEN=<read-only token> audit-gitlab-repo.sh <group/project>
# Env:   GITLAB_URL (default https://gitlab.example.com), EXPECTED_VISIBILITY (default private)
# Exit codes: 0 all checks pass, 1 runtime failure, 2 bad usage, 3 baseline findings.
#
set -Eeuo pipefail

readonly SCRIPT_NAME="${0##*/}"
readonly GITLAB_URL="${GITLAB_URL:-https://gitlab.example.com}"
readonly EXPECTED_VISIBILITY="${EXPECTED_VISIBILITY:-private}"
findings=0

die() { printf '%s ERROR: %s\n' "$SCRIPT_NAME" "$*" >&2; exit 1; }
usage() { printf 'Usage: GITLAB_TOKEN=... %s <group/project>\n' "$SCRIPT_NAME" >&2; exit 2; }

# GET only. The token goes through a file descriptor, not the process arguments.
# timeout is GNU coreutils (install coreutils on macOS, where it is gtimeout).
api() {
  timeout 60 curl -sS --fail --max-time 30 \
    -K <(printf 'header = "PRIVATE-TOKEN: %s"\n' "$GITLAB_TOKEN") \
    "${GITLAB_URL}/api/v4/$1"
}

uri() { jq -rn --arg v "$1" '$v | @uri'; }

# check <description> <jq expression> <json>; the expression yields true, false or "n/a"
check() {
  local result
  result="$(jq -r "$2" <<<"$3")"
  case "$result" in
    true) printf 'PASS  %s\n' "$1" ;;
    n/a) printf 'SKIP  %s (not available: plan, version or permission)\n' "$1" ;;
    *) printf 'FAIL  %s\n' "$1"; findings=$((findings + 1)) ;;
  esac
}

main() {
  [[ $# -eq 1 ]] || usage
  [[ -n "${GITLAB_TOKEN:-}" ]] || die "GITLAB_TOKEN is not set"
  command -v jq >/dev/null || die "jq is required"

  local project_id project default_branch protection
  project_id="$(uri "$1")"
  project="$(api "projects/${project_id}")" || die "cannot read project $1"
  default_branch="$(jq -r '.default_branch' <<<"$project")"
  protection="$(api "projects/${project_id}/protected_branches/$(uri "$default_branch")" 2>/dev/null)" \
    || protection='{"not_protected": true}'

  printf 'Project %s, default branch %s\n' "$1" "$default_branch"
  check "visibility is ${EXPECTED_VISIBILITY}" ".visibility == \"${EXPECTED_VISIBILITY}\"" "$project"
  check "not archived" '.archived == false' "$project"
  check "merge method is merge commit" '.merge_method == "merge"' "$project"
  check "pipelines must succeed" '.only_allow_merge_if_pipeline_succeeds == true' "$project"
  check "skipped pipelines do not allow merge" '.allow_merge_on_skipped_pipeline != true' "$project"
  check "all threads resolved before merge" '.only_allow_merge_if_all_discussions_are_resolved == true' "$project"
  check "source branch removed after merge" '.remove_source_branch_after_merge == true' "$project"
  check "secret push protection enabled" \
    'if has("secret_push_protection_enabled") then .secret_push_protection_enabled == true else "n/a" end' "$project"
  check "default branch is protected" '.not_protected != true' "$protection"
  check "force push blocked" '.allow_force_push == false' "$protection"
  check "nobody pushes directly" \
    '[.push_access_levels[]?.access_level] | (length > 0 and all(. == 0))' "$protection"
  check "code owner approval required" \
    'if has("code_owner_approval_required") then .code_owner_approval_required == true else "n/a" end' "$protection"

  if [[ "$findings" -gt 0 ]]; then
    printf '%s: %d finding(s)\n' "$SCRIPT_NAME" "$findings" >&2
    exit 3
  fi
}

main "$@"
```

Access level `0` means "no access" for push and merge levels, so a default branch where every push entry is `0` accepts changes only through merge requests. A protected branch entry that grants push to a user or group shows a different level and is reported.

### Settings audit: GitHub

```bash title="scripts/audit-github-repo.sh"
#!/usr/bin/env bash
#
# audit-github-repo.sh - read-only audit of one GitHub repository's baseline settings.
#
# Usage: audit-github-repo.sh <owner/repo>   (gh must be authenticated with read access)
# Exit codes: 0 all checks pass, 1 runtime failure, 2 bad usage, 3 baseline findings.
#
set -Eeuo pipefail

readonly SCRIPT_NAME="${0##*/}"
findings=0

die() { printf '%s ERROR: %s\n' "$SCRIPT_NAME" "$*" >&2; exit 1; }
usage() { printf 'Usage: %s <owner/repo>\n' "$SCRIPT_NAME" >&2; exit 2; }

check() {
  local result
  result="$(jq -r "$2" <<<"$3")"
  case "$result" in
    true) printf 'PASS  %s\n' "$1" ;;
    n/a) printf 'SKIP  %s (not visible: plan or permission)\n' "$1" ;;
    *) printf 'FAIL  %s\n' "$1"; findings=$((findings + 1)) ;;
  esac
}

main() {
  [[ $# -eq 1 ]] || usage
  local repo branch rules owners_errors
  repo="$(gh api "repos/$1")" || die "cannot read repository $1"
  branch="$(jq -r '.default_branch' <<<"$repo")"
  # Rules from active rulesets that apply to the default branch. Classic branch
  # protection is not included: read it with gh api repos/OWNER/REPO/branches/BRANCH/protection.
  rules="$(gh api "repos/$1/rules/branches/${branch}")" || die "cannot read rules for ${branch}"
  owners_errors="$(gh api "repos/$1/codeowners/errors" 2>/dev/null)" || owners_errors='{"errors": "n/a"}'

  printf 'Repository %s, default branch %s\n' "$1" "$branch"
  check "visibility is private" '.visibility == "private"' "$repo"
  check "merge commits only" '.allow_merge_commit and (.allow_squash_merge | not) and (.allow_rebase_merge | not)' "$repo"
  check "head branches deleted on merge" '.delete_branch_on_merge == true' "$repo"
  check "secret scanning push protection" \
    'if .security_and_analysis.secret_scanning_push_protection.status then .security_and_analysis.secret_scanning_push_protection.status == "enabled" else "n/a" end' "$repo"
  check "pull request required" 'any(.[]; .type == "pull_request")' "$rules"
  check "code owner review required" \
    'any(.[]; .type == "pull_request" and .parameters.require_code_owner_review == true)' "$rules"
  check "stale reviews dismissed" \
    'any(.[]; .type == "pull_request" and .parameters.dismiss_stale_reviews_on_push == true)' "$rules"
  check "status checks required" 'any(.[]; .type == "required_status_checks")' "$rules"
  check "force push blocked" 'any(.[]; .type == "non_fast_forward")' "$rules"
  check "deletion blocked" 'any(.[]; .type == "deletion")' "$rules"
  check "CODEOWNERS has no errors" 'if .errors == "n/a" then "n/a" else (.errors | length == 0) end' "$owners_errors"
  # SHOULD, so reported but not counted
  if [[ "$(jq -r 'any(.[]; .type == "required_signatures")' <<<"$rules")" != "true" ]]; then
    printf 'WARN  signed commits not required (SHOULD)\n'
  fi

  if [[ "$findings" -gt 0 ]]; then
    printf '%s: %d finding(s)\n' "$SCRIPT_NAME" "$findings" >&2
    exit 3
  fi
}

main "$@"
```

Run either script against a list of repositories from the central audit job and send the failures to each owner as a ticket, not a page. For organisation-wide audits, iterate over the group or organisation listing; paginate it, since list endpoints return one page at a time.

> [!warning] Not verified
> The scripts were written against the API references and not run against a live GitLab or GitHub. Not checked: the minimal token scopes for read-only access (GitLab `read_api` and GitHub fine-grained read permissions are the likely candidates), whether `security_and_analysis` is visible without admin access, whether rules in an `evaluate` ruleset appear in `rules/branches`, the endpoint for changing secret push protection on GitLab (the project field `secret_push_protection_enabled` is read-only here), and the GitLab access level numbers other than `0`. Test both scripts on one repository you know is compliant and one you know is not before they report to teams.

## New repositories

1. Create the repository from the golden path template ([[architecture/golden-path-templates-architecture]]), never empty. The template carries the files above, the CI include and the descriptor.
2. Apply the settings from code: Terraform for GitLab projects and GitHub repositories, or the organisation's provisioning job. Settings changed by hand are drift.
3. Register the descriptor in the catalog and set the tier ([[service-tiering-standard]]).
4. Run the settings audit once before the first merge request; a new repository starts compliant.

## Exceptions

A repository that cannot meet a rule (a mirror of an upstream project, a plan without code owners, an archived repository kept for reference) records the rule, the reason, an owner and an expiry date (proposed default 90 days) through [[compliance/policy-exception-and-waiver-process]]. Unprotected default branches, human bypass actors and missing owners are not accepted as exceptions.

## Reviewer checklist

- [ ] README with owner, tier and data class (where relevant), local run, deploy and rollback, and runbook links.
- [ ] CODEOWNERS with team aliases, default rule first, CI and policy paths owned, no errors reported.
- [ ] `catalog-info.yaml` names an owner group that exists.
- [ ] `.gitignore`, `.editorconfig` and `.pre-commit-config.yaml` with the secret scan.
- [ ] CI includes the central templates at a pinned version; dependency update configuration exists.
- [ ] Default branch: no direct push, no force-push, no deletion, reviewed merge with passing pipelines, code-owner approval.
- [ ] Merge commits; source branches deleted after merge; `v*` tags protected.
- [ ] Secret push protection on where the plan has it, and the pipeline scan in any case.
- [ ] Private visibility unless released through the open-source process; `LICENSE` and `SECURITY.md` when public.
- [ ] Both audit scripts pass, or each finding has an exception with an expiry.
